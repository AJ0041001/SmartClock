---

## 1. 帧格式

固定 **10 字节**，小端序（Little-Endian）：

| 字节 | 名称 | 值 | 说明 |
|:---:|---|---|---|
| 0 | HEADER_1 | `0xAA` | 帧头 1 |
| 1 | HEADER_2 | `0x55` | 帧头 2 |
| 2 | LEN | `0x06` | 有效载荷长度，固件硬性校验必须为 6 |
| 3 | TYPE | `0x01` / `0x02` | 控制类型 |
| 4 | X_L | — | X 坐标低字节 |
| 5 | X_H | — | X 坐标高字节 |
| 6 | Y_L | — | Y 坐标低字节 |
| 7 | Y_H | — | Y 坐标高字节 |
| 8 | RESERVED | `0x00` | 保留字段 |
| 9 | CRC8 | — | 校验值 |

### TYPE 取值

| 值 | 含义 | 视觉端何时用 |
|:---:|---|---|
| `0x01` | 串口坐标与按键共同控制。串口坐标作为基准，按键移动量叠加其上 | **正常追踪时** |
| `0x02` | 只使用按键控制。X/Y 仍须填写并通过 CRC，但不改变挡板位置 | **丢失色块时**，主动交还控制权 |

固件只接受这两个值，其它一律判为无效帧。

## 2. CRC-8 算法

**参数**

| 项 | 值 |
|---|---|
| 多项式 | `0x07` |
| 初值 | `0x00` |
| 输入反射 | 否 |
| 输出异或 | 否 |
| **计算范围** | **字节 2 ~ 8，共 7 字节** |
| 比对位置 | 字节 9 |

> ⚠️ 注意：CRC 范围**包含保留字节 8**。这是个容易写错的地方 ——
> 固件里的调用是 `bsp_game_crc8(&bsp_game_frame[2], 7U)`。

**固件原版实现**（`Code/BSP/Src/bsp_board.c:208`）

```c
static uint8_t bsp_game_crc8(const uint8_t *data, uint8_t length)
{
  uint8_t crc = 0U;

  for (uint8_t i = 0U; i < length; i++)
  {
    crc ^= data[i];
    for (uint8_t bit = 0U; bit < 8U; bit++)
      crc = (crc & 0x80U) ? (uint8_t)((crc << 1U) ^ 0x07U)
                          : (uint8_t)(crc << 1U);
  }
  return crc;
}
```

**Python 实现**（`src/protocol.py`）

```python
def crc8(data: bytes) -> int:
    crc = 0x00
    for byte in data:
        crc ^= byte
        for _ in range(8):
            crc = ((crc << 1) ^ 0x07) & 0xFF if crc & 0x80 else (crc << 1) & 0xFF
    return crc
```

> C 语言里 `uint8_t` 的算术在 8 位处自然回绕，Python 必须显式 `& 0xFF`。

## 3. 坐标系

### 屏幕布局

```
    480 x 800 屏幕
    ┌───────────────────────────┐
    │                           │
    │   ┌───────────────────┐   │ ← 白色外框 430x590，左上角 y=78，边框 3px
    │   │                   │   │
    │   │   游戏内部区      │   │   内部有效区域 424 x 584
    │   │   424 x 584       │   │   内部坐标原点 = 框内侧左上角 (0,0)
    │   │                   │   │   +X 向右，+Y 向下
    │   │  ═══════════      │   │ ← 红色挡板 70 x 13
    │   └───────────────────┘   │
    │                           │
    └───────────────────────────┘
```

### 挡板与中心坐标

程序内部保存的是挡板**左上角**坐标：

```
挡板左上角 X 范围：0 .. 354     (= 424 - 70)
挡板左上角 Y 范围：0 .. 571     (= 584 - 13)
```

但**视觉端发送的是挡板中心坐标**，有效范围为：

```
中心 X：35 .. 389               (= 0+35 .. 354+35，35 = 70/2)
中心 Y：6  .. 578               (= 0+6  .. 571+6，6  ≈ 13/2)
```

固件接收后自动转换并限幅：

```
挡板左上角 X = clamp(中心 X, 35, 389) - 35
挡板左上角 Y = clamp(中心 Y, 6, 578) - 6
```

**因此视觉端发送越界坐标是安全的**，单片机会把挡板贴到最近的边界而不会
出界。不过本实现默认发送前先限幅，让串口日志更干净、便于排查。

## 4. 单片机回传

| 情况 | 回传字节 |
|---|---|
| 帧有效 | `OK\r\n` （4 字节） |
| 帧无效 | `ERROR\r\n` （7 字节） |

视觉端应按完整字符串接收。本实现用 `read_until` 读到 `\r\n` 为止。

> 固件用"接收空闲中断 + 响应队列"实现，实际发送由 LVGL 任务完成，
> 所以回传可能比预期稍慢（通常几毫秒，极端情况下几十毫秒）。
> `serial.timeout` 默认 0.5 秒足够。

## 6. 超时回退行为

协议规定：

> 如果一段时间没有收到新的串口帧，程序会自动回退到按键控制，
> 并保持挡板当前位置不跳变。

这意味着视觉端**不能长时间停发**。本实现的策略是：

1. 正常追踪时按 `loop.target_fps` 持续发 TYPE=01 帧（默认 20 fps）
2. 连续 `loop.lost_frames` 帧（默认 5）检不到色块 → 判定丢失，
   主动发一帧 TYPE=02 交还控制权
3. 丢失期间每 1 秒重申一次 TYPE=02，避免行为不确定
4. 重新检出色块后，等 `loop.reacquire_delay` 秒让平滑器收敛，
   再恢复发 TYPE=01，防止挡板从旧位置猛跳

## 7. 实现注意事项

**帧同步的容错**：固件 `bsp_game_feed_byte` 的同步策略比较特别 ——
在等待第二个帧头时若又收到 `0xAA`，会把新收到的当作帧首（而不是
丢弃整帧）。本项目的 `FrameAssembler` 完整复刻了这个行为并有测试覆盖。

**保留字节参与 CRC**：改保留字节会改变 CRC。目前固定 `0x00`。

**小端序**：X/Y 都是低字节在前。写错字节序会导致挡板位置离谱
（比如 X=212 写成 `00 D4` 会被解析成 54272，然后被限幅到 389，
表现为"挡板总是贴右边"）。

**波特率**：固件用 115200。两边必须一致，否则收到的是乱码，
CRC 必然失败，单片机回 `ERROR`。
