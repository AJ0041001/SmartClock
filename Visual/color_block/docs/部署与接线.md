# 部署与接线

面向鲁班猫 4（RK3588S, aarch64, Ubuntu 26.04）+ USB 摄像头 + STM32 的完整部署说明。

---

## 一、硬件清单

| 部件 | 说明 |
|---|---|
| 鲁班猫 4 V1R0 | RK3588S，本方案运行平台 |
| USB 摄像头 | 标准 UVC 设备即可（本方案按彩钻风 USB 摄像头编写） |
| STM32 开发板 | 运行 SmartClock 固件（`Code/`） |
| 连接线 | 见下方"接线方案" |
| （可选）USB-TTL 转换器 | CH340 / CP2102 / FT232 / PL2303 均可 |

## 二、串口连接：两个方案

> **重要概念澄清**
> 固件里的 `USART2` 是 **STM32 侧**的外设名称。
> Linux 侧用哪个串口都可以 —— 协议只关心字节流，不关心你在板子上用的是
> uart0 还是 uart4。**只要两边波特率一致、TX/RX 交叉、共地即可。**

### 方案 A：USB-TTL 转换器（推荐，零配置）

**为什么推荐**：实测你板子上**所有 10 个板载 UART 目前在设备树里都是
`status = disabled`**，`/sys/class/tty/` 里只有 `ttyFIQ0`（调试串口）。
用 USB-TTL 就完全绕开设备树配置。

USB 转串口驱动在你这台机器上全部可用：

```
ch341.ko      ✅        cp210x.ko     ✅
ftdi_sio.ko   ✅        pl2303.ko     ✅
```

插上后内核自动创建 `/dev/ttyUSB0`，无需任何额外操作。

**接线**（三根线就够）：

| USB-TTL | STM32 | 说明 |
|---|---|---|
| TX | RX（USART2_RX） | **必须交叉** |
| RX | TX（USART2_TX） | **必须交叉** |
| GND | GND | **必须共地**，否则通信不稳定 |
| （不接 VCC） | | 两边各自独立供电，避免电源冲突 |

> ⚠️ 最常见的三个错误：TX 接 TX、忘记共地、两边都供 3.3V 造成倒灌。

### 方案 B：使用板载 40pin 排针 UART

需要**先在设备树里启用 UART**，否则 `/dev/ttyS*` 根本不会出现。

**步骤 1：查看可用的 UART 插件**

野火为鲁班猫 4 提供了这些 40pin UART 插件（已确认存在于
`/boot/firmware/dtbs/rockchip/overlay/`）：

| 插件名 | UART |
|---|---|
| `rk3588-lubancat-uart0-m2-overlay` | uart0 |
| `rk3588-lubancat-uart4-m2-overlay` | uart4 |
| `rk3588-lubancat-uart5-m1-overlay` | uart5 |
| `rk3588-lubancat-uart7-m1-overlay` | uart7 |
| `rk3588-lubancat-uart7-m2-overlay` | uart7 |
| `rk3588-lubancat-uart9-m2-overlay` | uart9 |

> 注意：uart2 是板子的调试串口，**不在**可选的 40pin 插件里。

**步骤 2：编辑启动配置**

```bash
sudo nano /boot/firmware/ubuntuEnv.txt
```

找到 `overlays=` 那一行，把要用的 UART 插件追加到**同一行**（空格分隔）：

```
overlays=rk3588s-lubancat-dp0-in-vp1-overlay rk3588s-lubancat-4-hdmi0-overlay rk3588-lubancat-uart4-m2-overlay
```

> 关键：**所有插件必须写在同一行**。这也是该文件注释里强调的。

**步骤 3：重启并确认**

```bash
sudo reboot
```

重启后：

```bash
ls /dev/ttyS*
```

应该能看到对应的设备节点（uart4 → `/dev/ttyS4`）。

**步骤 4：查引脚位置**

具体哪两个物理引脚是 TX/RX，**请对照野火官方文档的 40pin 引脚图**：

→ [鲁班猫-RK3588 系列快速使用手册 · 40PIN 引脚对照图](https://doc.embedfire.com/linux/rk3588/quick_start/zh/latest/quick_start/40pin/40pin.html)

（引脚复用关系随 `m0/m1/m2` 后缀不同而变化，务必以官方图为准，
不要凭经验猜。）

## 三、串口权限

Linux 下普通用户默认不能访问串口设备。**两种解决办法，任选其一。**

**办法 1（推荐）：把用户加入 dialout 组**

```bash
sudo usermod -aG dialout $USER
```

**执行完必须注销重新登录**（或重启）才生效。验证：

```bash
groups          # 输出里应该包含 dialout
```

**办法 2：临时用 sudo 运行**

```bash
sudo python3 scripts/main.py
```

> 如果报错 `Permission denied: '/dev/ttyUSB0'`，就是这个问题。
> 本项目的 `scripts/serial_test.py` 会在打不开时自动提示这条。

## 四、部署步骤

### 1. 拷贝项目到板子

整个 `color_block/` 目录拷过去即可，**无需安装任何 Python 包**
（串口用标准库 `termios` 实现，不依赖 pyserial）。

```bash
scp -r color_block cat@<板子IP>:~/
```

### 2. 确认依赖

```bash
cd ~/color_block
bash tools/install.sh --check
```

### 3. 跑离线验证

```bash
python3 scripts/demo_offline.py
```

不需要任何硬件。看到 `✅ 离线演示完成` 说明软件正常。

### 4. 接入摄像头

插上 USB 摄像头：

```bash
python3 scripts/camera_check.py --probe-all
```

把找到的节点号写进 `config.yaml`：

```yaml
camera:
  index: 0        # 按实际结果修改
```

### 5. 现场标定

见 `标定指南.md`。默认用 YOLO 引擎时**只需要框两个 ROI**（不需要取色）：

```bash
python3 scripts/main.py --dry-run
```

窗口里按 `r` 在画面点两下框映射区、按 `0` 定检测区、按 `s` 写回。
想单独用预览脚本标定也可以：

```bash
python3 scripts/preview.py --camera --write-roi
```

（`color_pick.py` 只在用 HSV 降级方案时才需要。）

### 6. 空跑确认

```bash
python3 scripts/main.py --dry-run --preview
```

**这一步一定要做。** 屏幕上会实时显示当前会发出的游戏坐标，
确认色块右移时 `GAME` 的 X 也在增大，方向没反。

同时把卡片沿 A 的四条边和四个角各走一遍，**看 B（绿色虚线）会不会变红**。
一旦变红说明 B 太小、卡片被裁过，中心会偏 —— 按 `B +10` 放大。
这也是"挡板到不了最边上"的直接原因。

### 7. 接通串口

```bash
python3 scripts/serial_test.py --probe
```

让它自动找出哪个串口接了 STM32（判据是"谁能回 `OK`"）。

### 8. 正式运行

```bash
python3 scripts/main.py
```

## 五、开机自动启动（可选）

如果需要开机就自动开始追踪，用 systemd 用户服务：

```bash
mkdir -p ~/.config/systemd/user

cat > ~/.config/systemd/user/smartclock-vision.service <<'EOF'
[Unit]
Description=SmartClock 色块视觉追踪
After=graphical-session.target

[Service]
Type=simple
WorkingDirectory=%h/color_block
ExecStart=/usr/bin/python3 scripts/main.py
Restart=on-failure
RestartSec=5

[Install]
WantedBy=default.target
EOF

systemctl --user daemon-reload
systemctl --user enable --now smartclock-vision.service
```

查看状态与日志：

```bash
systemctl --user status smartclock-vision.service
journalctl --user -u smartclock-vision.service -f
```

> 如果你的串口需要 root 权限，在 `[Service]` 段加上 `SupplementaryGroups=dialout`
> 会比直接用 root 运行更安全。

## 六、性能参考

在 RK3588S 上的实测（640×480 MJPG，程序内计时）：

| 环节 | 单帧耗时 |
|---|---|
| 采集（USB 读取） | 由摄像头帧率决定，30fps 下约 33 ms |
| HSV 转换 + 阈值 | 约 3~6 ms |
| 形态学（5×5，2 次迭代） | 约 4~8 ms |
| 轮廓 + 矩质心 | < 1 ms |
| 帧构造 + 串口写 | < 1 ms |
| **合计（不含采集等待）** | **约 8~15 ms** |

因此 CPU 侧完全能跟上 20~30 fps 的发送节奏。若觉得不够快，可以：

- 把 `detector.morph_iterations` 从 2 降到 1
- 把 `detector.blur_size` 从 5 降到 3
- 降低分辨率到 320×240（精度够用的话）
