# SmartClock_F407 工程设计说明

## 1. 工程组成

本工程运行在 STM32F407 上，使用以下软件和硬件模块：

```text
STM32F407
├─ HAL 外设驱动
├─ FreeRTOS / CMSIS-RTOS2
├─ LVGL 8.3.11
├─ FatFs
├─ FSMC LCD
├─ SDIO SD 卡
├─ I2C1 + WM8978 寄存器配置
├─ I2S2 + DMA 音频输出
├─ ADC1 + 定时采样
├─ DAC1 + 定时器触发/DMA
├─ RTC
├─ USART2 游戏坐标输入
└─ 按键、LED、蜂鸣器
```

代码分工如下：

- `Core/Src/main.c`：HAL 初始化、FreeRTOS 线程创建、默认任务、音频任务、TIM7 时基和整点报时检查；
- `BSP/Src/bsp_board.c`：LCD、SD/FatFs、ADC、DAC、WM8978/I2S、音频播放、RTC 闹钟和 USART2；
- `BSP/Src/bsp_lvgl.c`：LVGL 显示驱动、按键输入、所有页面、页面缓存、游戏逻辑和设置保存；
- `BSP/Src/bsp_touch.c`：触摸采样接口；
- `Middlewares/Third_Party/lvgl`：LVGL 8.3.11 源码；
- `Middlewares/Third_Party/FreeRTOS`：FreeRTOS 内核和 ARM Cortex-M4F 移植层。

## 2. 启动和任务结构

`main()` 中的实际启动顺序是：

```c
HAL_Init();
SystemClock_Config();
MX_GPIO_Init();
MX_DMA_Init();
MX_FSMC_Init();             /* 已注释，LCD 驱动内部负责 FSMC */
MX_SDIO_SD_Init();
MX_FATFS_Init();
MX_ADC1_Init();
MX_DAC_Init();
MX_I2S2_Init();
MX_USART1_UART_Init();
MX_USART2_UART_Init();
MX_RTC_Init();
BSP_Board_Init();
BSP_LCD_InitAndShow();
BSP_LVGL_Init();
osKernelInitialize();
MX_FREERTOS_Init();
osKernelStart();
```

工程创建三个线程：

| 线程 | 函数 | 当前职责 |
|---|---|---|
| 默认任务 | `StartDefaultTask` | USART2 回传、LED 交替、RTC 整点检查、ADC 自检和让出 CPU |
| LVGL 任务 | `BSP_LVGL_Task` | `lv_timer_handler()`、页面业务、闹钟、时钟、ADC 页面和游戏刷新 |
| 音频任务 | `StartAudioTask` | 调用 `BSP_Audio_ProcessPending()` 处理待播放音频 |

`osKernelInitialize()` 初始化 RTOS 内核对象；`osKernelStart()` 启动调度器。调度器启动后，`main()` 不再执行普通循环，持续工作由三个线程完成。

## 3. LCD 和 LVGL 刷新

LCD 逻辑分辨率为 `480 × 800`。LCD 通过 FSMC 连接，LCD 初始化函数内部完成 FSMC/LCD 寄存器初始化，因此 `main.c` 中的 `MX_FSMC_Init()` 保持注释，避免同一总线被初始化两次。

LVGL 使用 480×10 行的单个绘图缓冲区：

```c
#define LVGL_HOR_RES  480U
#define LVGL_VER_RES  800U
#define LVGL_BUF_LINES 10U
static lv_color_t lvgl_draw_buf_mem[480U * 10U];
```

`BSP_LVGL_Init()` 依次初始化 LVGL、读取 Flash 设置、初始化绘图缓冲区、注册 `lvgl_flush_cb()`、注册 480×800 显示设备并创建主页面和告警弹窗页面。

`lvgl_flush_cb()` 只把 LVGL 提交的脏矩形区域写入 LCD，刷新结束调用 `lv_disp_flush_ready()`。时钟指针、ADC 波形、游戏星星和爆炸效果只刷新各自区域，不执行整屏清屏。

LVGL 使用 Cube HAL 的毫秒计时：

```c
#define LV_TICK_CUSTOM 1
#define LV_TICK_CUSTOM_SYS_TIME_EXPR (HAL_GetTick())
```

因此 `BSP_LVGL_TickInc()` 不重复累加 LVGL 时钟，`BSP_LVGL_Task()` 直接使用 `lv_tick_get()` 和 `HAL_GetTick()`。LVGL 的唯一调用线程是 `BSP_LVGL_Task()`。

## 4. LVGL 页面和三页留存池

主页面和闹钟告警页面在 `ui_create()` 中创建并长期保留。功能页面在第一次进入时创建：

```text
主菜单
├─ Time Settings
├─ ADC
├─ DAC
├─ Alarm
├─ Voice Packs
└─ Game
```

页面缓存由 9 个槽位组成：

```text
Settings、DAC、ADC、Alarm Menu、Alarm Edit、Game、
Audio Menu、Voice Chime、Game Music
```

缓存上限为 3 个页面。每个页面进入时更新递增访问序号：

1. 页面指针为空时创建页面；
2. 缓存数量小于 3 时加入缓存；
3. 缓存数量达到 3 时查找访问序号最小的非当前页面；
4. 从 LVGL group 移除该页面控件；
5. 调用 `lv_obj_del()` 删除页面对象；
6. 清空页面指针和控件指针；
7. 创建新页面并记录访问序号。

页面删除只释放 LVGL 对象，不删除业务状态。RTC、闹钟、音频、ADC、DAC、游戏分数、游戏难度和设置变量均独立保存；再次进入页面时，控件根据这些变量重新显示。

## 5. 按键控制

按键通过 LVGL keypad 输入设备进入 `ui_group`，页面事件统一在 `ui_button_event()` 中处理：

```text
UP/BACK：返回上一级
KEY1：确认、进入子菜单
KEY2：向右或增大
KEY3：向左或减小
```

长按由任务中的按键状态和持续时间处理。页面切换、参数修改和控件焦点变化均在 LVGL 任务中执行。

## 6. USART2 空闲接收和游戏坐标

USART2 使用 `HAL_UARTEx_ReceiveToIdle_IT()` 接收 64 字节线性缓冲区。`HAL_UARTEx_RxEventCallback()` 在接收空闲或缓冲区满时：

1. 根据 `size` 逐字节送入游戏帧状态机；
2. 完成帧头同步、固定长度判断和 CRC8 校验；
3. 有效帧写入最新坐标快照并增加 generation 计数；
4. 有效/无效结果写入回传队列；
5. 重新开启 `HAL_UARTEx_ReceiveToIdle_IT()`。

中断回调不调用 LVGL、不刷新 LCD、不执行 `snprintf()`。`BSP_GameSerial_Service()` 在默认任务中取出回传结果：

```text
有效帧：OK\r\n
无效帧：ERROR\r\n
```

当前固定 10 字节帧格式：

```text
字节 0：0xAA
字节 1：0x55
字节 2：0x06
字节 3：TYPE，0x01 或 0x02
字节 4：X_L
字节 5：X_H
字节 6：Y_L
字节 7：Y_H
字节 8：保留，填 0x00
字节 9：CRC8
```

CRC8 的计算范围为字节 2 至字节 8，初值 `0x00`，多项式 `0x07`。

`TYPE=01` 时，串口坐标和按键移动共同作用；`TYPE=02` 时，串口坐标只完成接收和回传，挡板只由按键控制。超过 500 ms 未收到有效串口帧时，游戏自动回到按键控制。

游戏区域为 `430 × 590`，内部有效区域为 `424 × 584`。红色挡板尺寸为 `70 × 13`，位置在写入 LVGL 前被限制在游戏框内。

## 7. WM8978、I2S2 和音频任务

WM8978 的连接关系为：

```text
I2C1：配置 WM8978 寄存器
I2S2：输出 PCM 音频时钟和数据
DMA ：搬运 I2S2 音频数据
SDIO/FatFs：读取 WAV 文件
```

DAC 是 MCU 的模拟波形输出链路，与 WM8978 的 I2S 播放链路分开。

音频播放器读取 WAV 文件，跳过 WAV 文件头后将 PCM 数据填入音频缓冲区，通过 I2S2 DMA 输出。当前播放器使用 PCM、单声道、16 bit、16 kHz。

`StartAudioTask()` 每 1 ms 调用一次 `BSP_Audio_ProcessPending()`。新的音频请求会停止当前 DMA 播放、关闭旧文件、清理缓冲状态，再打开新文件播放。DMA 半传输和传输完成回调负责继续填充数据；文件结束后关闭文件并清除 busy 状态。

当前音频包映射为：

```text
MO LE：SD 卡根目录中的原有游戏音效
Miao：\Miao\xxl1.wav ~ xxl5.wav、xxljs.wav、xxlzd.wav
```

Miao 音效中接星星从 `xxl1.wav` 至 `xxl5.wav` 随机选择，游戏结束播放 `xxljs.wav`，接炸弹播放 `xxlzd.wav`。语音包、游戏音乐包和音量由 `BSP_Audio_SetVoicePack()`、`BSP_Audio_SetGameMusicPack()` 和 `BSP_Audio_SetVolume()` 设置。

## 8. RTC、闹钟和整点报时

RTC 读取固定为先读时间、再读日期：

```c
HAL_RTC_GetTime(&hrtc, &time, RTC_FORMAT_BIN);
HAL_RTC_GetDate(&hrtc, &date, RTC_FORMAT_BIN);
```

两个闹钟分别对应 RTC Alarm A 和 Alarm B。闹钟配置包含小时、分钟、秒和使能状态。RTC 中断只设置 pending 标志，实际页面跳转、蜂鸣器状态机和音频请求在 LVGL 任务中执行。

闹钟状态机为：

```text
RTC 触发
  -> 弹出告警页面
  -> 蜂鸣器连续短响三声，间隔后重复
  -> KEY1：关闭闹钟
  -> UP/BACK：延迟 5 分钟
  -> 30 秒无按键：自动延迟 5 分钟
  -> 延迟后再次无响应：关闭本次闹钟
```

整点报时由默认任务检查，触发条件为 `分钟=0 且 秒<5`。日期和小时组成唯一 key，同一整点只请求一次音频。时间设置页面处于活动状态时禁止报时；退出时间设置页面后恢复整点检查。整点报时开关默认关闭，设置保存在 Flash。

## 9. ADC 示波器

ADC1 持续采集数据，BSP 层保存采样结果并计算直流电压、峰峰值、频率、占空比和波形类型。

ADC 页面每 250 ms 更新一次，只更新示波器曲线区域和测量标签，不刷新整个页面。采样值经过平均和滞回阈值处理，测频使用多个周期结果，波形分类包含正弦波、方波、三角波、锯齿波和 Unknown。

低频信号使用较长时间窗口，高频信号使用较短时间窗口；曲线显示点数根据当前窗口压缩到固定显示区域。波形分类在连续结果稳定后才更新标签，避免在相邻类型之间快速跳变。

## 10. DAC 波形输出

DAC 页面控制以下参数：

```text
波形：正弦波、方波、三角波、锯齿波
频率：0~2000 Hz，步进 0.1 Hz
峰峰值：步进 0.1
占空比：参数可调
输出：开始/暂停
```

频率显示采用数字位选择框，默认选择个位；确认后切换选择位，增减操作在选定位上完成并支持十进制进位/借位。DAC 使用查表数据、定时器触发和 DMA 输出，修改波形或参数时重新生成采样表和触发周期。

## 11. 游戏和难度

游戏页面区域为 `430 × 590`，白色游戏框内部用于生成星星和炸弹，底部挡板尺寸为 `70 × 13`。星星和炸弹在生成时检查间距，避免对象重合。对象每 100 ms 更新一次位置，速度由难度决定：

| 难度 | 活动星星数量 | 下落速度 |
|---|---:|---:|
| 简单 | 2 | 3~8 px/帧 |
| 中等 | 4 | 5~15 px/帧 |
| 困难 | 6 | 8~20 px/帧 |

游戏拥有 3 个生命值。接到星星加分并随机播放星星音效；接到炸弹触发全向爆炸效果并熄灭一个生命图标；生命值全部耗尽后显示 Game Over 页面并播放结束音效。

游戏最高分和最近 5 次分数保存在 RAM，并在游戏结束时写入 Flash。Game Over 页面显示当前分数、最高分和最近分数记录。

## 12. Flash 设置和历史记录

Flash 第 11 扇区保留给设置和游戏记录：

```text
起始地址：0x080E0000
结束地址：0x080FFFFF
扇区大小：0x20000
记录版本：3
```

程序链接脚本将程序镜像限制在前面的 Flash 区域，避免覆盖第 11 扇区。

每条记录包含 magic、版本号、递增 sequence、校验值、最高分、最近 5 次分数、DAC 配置、Alarm A/B 配置、整点报时开关、语音包、游戏音乐包、音量、游戏难度和 RTC 时间记录。

记录采用追加式 journal：

```text
扫描现有记录
  -> 找到 sequence 最大且校验正确的记录
  -> 载入最新设置

保存设置
  -> 直接写入下一个空记录槽
  -> 写入后逐字验证
  -> 更新 sequence
  -> 当前扇区写满后才擦除第 11 扇区
```

设置修改过程中只修改 RAM，不擦除 Flash。离开设置页面返回主菜单时保存；游戏结束记录分数时保存。时间设置完成后，当前时间写入 RTC，并随 RTC 后备电源继续运行。

## 13. CubeMX 生成文件边界

CubeMX 重新生成后，自定义内容位于独立 BSP 文件或用户代码区：

- LVGL 页面和页面缓存：`BSP/Src/bsp_lvgl.c`；
- LCD、音频、ADC、DAC、SD、串口和闹钟：`BSP/Src/bsp_board.c`；
- BSP 接口声明：`BSP/Inc/bsp_board.h`；
- 默认任务、LVGL 任务和音频任务创建：`Core/Src/main.c` 的用户代码区；
- LVGL 配置：`Core/Inc/lv_conf.h`；
- Flash 保留范围：`MDK-ARM/SmartClock_F407/SmartClock_F407.sct`。

CubeMX 生成文件中的用户代码区保留任务创建、BSP 初始化和整点报时逻辑；BSP 源码不由 CubeMX 覆盖。外设引脚、DMA Stream、NVIC 优先级、LVGL 配置和 Flash 链接范围与当前工程保持一致。
