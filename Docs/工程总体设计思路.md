# SmartClock_F407 工程总体设计思路

## 1. 工程目标

本工程以 STM32F407 为主控，构建一个带 LCD 图形界面、RTC 时钟、音频播放、ADC/DAC 测试、SD 卡文件系统、游戏和按键/串口双输入的桌面时钟系统。整体设计目标是：

- 硬件驱动与界面代码分层，便于单独测试和替换；
- LVGL 只由一个 GUI 线程操作，避免多线程同时访问 LVGL 导致卡死；
- 音频、闹钟、游戏等功能在页面销毁后仍继续运行；
- 设置和游戏记录掉电保存，但避免频繁擦写 Flash；
- 长耗时操作不阻塞系统时基、GUI 刷新和按键响应。

## 2. 软件分层

```text
应用层
├─ 主菜单、时间设置、DAC、ADC 示波器、闹钟、游戏、语音包选择
├─ 页面事件处理和控件状态
└─ 游戏/闹钟/整点报时等业务逻辑

BSP 层
├─ bsp_lvgl.c       LVGL 页面、输入、显示刷新、GUI 任务
├─ bsp_board.c      LCD、音频、ADC、DAC、SD、按键、串口游戏输入
├─ bsp_touch.c      触摸采样与坐标转换
└─ Flash 设置记录、音频文件选择和播放调度

中间件层
├─ LVGL 8.3.11
├─ FreeRTOS / CMSIS-RTOS2
├─ FatFs
└─ STM32 HAL

硬件抽象层
├─ STM32F4 HAL
├─ FSMC/FMC LCD 总线
├─ SDIO + DMA/中断
├─ I2S2 + DMA + WM8978
├─ ADC/DAC/TIM
└─ USART2 空闲接收
```

原则是：页面只负责显示和产生用户操作，真正的功能状态放在业务变量中；驱动只提供初始化、启动、停止、读取和播放接口，不直接依赖某个页面是否存在。

## 3. FreeRTOS 与任务模型

系统启动顺序建议保持为：

```c
HAL_Init();
SystemClock_Config();
MX_GPIO_Init();
MX_DMA_Init();
MX_USARTx_UART_Init();
MX_RTC_Init();
MX_ADC_Init();
MX_DAC_Init();
MX_I2S2_Init();
MX_SDIO_SD_Init();
MX_FATFS_Init();
BSP_Board_Init();
osKernelInitialize();
MX_FREERTOS_Init();
osKernelStart();
```

`osKernelInitialize()` 只初始化 RTOS 内核对象和调度器状态，不会自动初始化 LCD、音频或 LVGL。`osKernelStart()` 之后调度器接管 CPU，原来 `main()` 里的普通 `while(1)` 不再承担持续刷新职责。

推荐的任务职责如下：

| 任务 | 主要职责 | 时间要求 |
|---|---|---|
| `BSP_LVGL_Task` | `lv_timer_handler()`、页面业务轮询、局部数据刷新 | 周期约 5 ms，不能调用阻塞式长操作 |
| 音频调度任务/回调 | 维护音频队列、DMA 完成后切换下一个 WAV | 由 DMA 回调或短周期轮询驱动 |
| 采样任务 | ADC/DAC 采样缓存、测频、峰峰值和占空比计算 | 采样与显示计算分离 |
| 闹钟逻辑 | 比较 RTC、触发/停止/延迟闹钟 | 10~100 ms 轮询即可 |
| 串口接收 | 主要由 UART 空闲中断/DMA 完成，任务只消费完整帧 | 不在中断中解析复杂协议 |

只有 GUI 任务可以调用 `lv_` 开头的函数。其他任务如果要更新界面，应通过事件标志、消息队列或共享业务变量通知 GUI 任务，由 GUI 任务完成控件更新。

## 4. LVGL 显示与刷新设计

### 4.1 显示驱动

LCD 使用现有 FSMC/FMC 并行总线驱动。LCD 初始化只保留一个入口，避免 CubeMX 生成的 `MX_FSMC_Init()` 与 LCD 驱动内部再次初始化同一外设，造成寄存器和时序冲突。

LVGL 显示端采用：

1. `lv_disp_draw_buf_t` 管理绘图缓冲区；
2. `flush_cb` 将脏矩形区域写入 LCD；
3. 每次刷新只传输 LVGL 请求的 `area`，不做整屏清屏；
4. 刷新完成后调用 `lv_disp_flush_ready()`；
5. `lv_tick_inc(1)` 只在 1 ms 时基中断中递增，且不在中断中执行 `lv_timer_handler()`。

如果使用阻塞式 FSMC 写屏，刷新速度受 LCD 总线写入速度限制；优化方向是扩大连续写入块、减少无意义的 `LCD_Clear()`、避免每次循环重复绘制同一文本，并在 LCD 驱动支持时使用 DMA。

### 4.2 LVGL 时基

```c
void BSP_LVGL_TickInc(void)
{
    lv_tick_inc(1U);
}
```

该函数只做计时累加。`lv_timer_handler()` 必须放在 `BSP_LVGL_Task` 中，并在末尾使用短时间 `osDelay()` 让出 CPU：

```c
for (;;) {
    lv_timer_handler();
    osDelay(5U);
}
```

禁止在 `lv_timer_handler()` 内部再次调用自身，也不要在 LVGL 回调里执行 SD 卡读取、Flash 擦除、长时间 UART 发送或阻塞式音频播放。

### 4.3 页面按需创建与三页留存池

页面采用“首次进入时创建、离开时隐藏”的策略。主菜单、时间设置、ADC、DAC、游戏和语音设置属于高频或功能性页面，可长期保留；普通子页面按需创建。

留存池的逻辑是：

```text
进入页面
  ├─ 页面已存在：直接加载并恢复焦点
  └─ 页面不存在：创建页面、加入留存池

留存池超过 3 个页面
  └─ 删除最久未访问的页面对象
```

这里删除的是 LVGL 页面对象，不是业务功能。闹钟、音频播放、ADC/DAC 采样、RTC 和游戏状态都保存在 BSP/业务变量或独立任务中，因此页面被回收后功能不会停止。再次进入页面时，只根据业务变量重新创建控件并显示当前状态。

为避免误删正在使用的页面，当前页面、主菜单和必须常驻页面不进入淘汰候选；回收前先从 `lv_group` 移除对象，再删除页面对象并清空指针。

## 5. 按键输入与串口输入

### 5.1 按键

按键驱动提供统一的逻辑键值，例如：

```text
KEY_UP/BACK : 返回上一级
KEY_1       : 确认/进入
KEY_2       : 上调或向右
KEY_3       : 下调或向左
```

最终菜单动作由 GUI 任务统一处理。长按在 GUI 任务中通过按下持续时间判断，不在 GPIO 中断里执行页面操作。

### 5.2 USART2 空闲中断接收

游戏外部坐标输入使用 USART2。连续数据流不能依赖固定长度轮询，因此采用 UART DMA + 空闲线检测：

```c
HAL_UARTEx_ReceiveToIdle_DMA(&huart2, rx_buffer, sizeof(rx_buffer));
```

在 `HAL_UARTEx_RxEventCallback()` 中只完成三件事：

1. 取得本次 DMA 收到的字节数；
2. 将数据复制到软件环形缓冲区或投递消息队列；
3. 重新开启 `ReceiveToIdle_DMA`。

完整协议解析放到普通任务中，避免在中断里执行 `snprintf`、LCD 操作或复杂校验。无效帧回复 `ERROR`，有效帧回复 `OK`。

推荐帧格式：

```text
AA 55 01 MODE X_L X_H Y_L Y_H CS
```

其中：

- `AA 55`：帧头；
- `01`：坐标控制模式，按键和串口共同作用；
- `02`：仅按键模式，串口坐标不改变位置；
- `X/Y`：目标坐标，小端 16 位；
- `CS`：从 `MODE` 到 `Y_H` 的 8 位累加和。

坐标接收后先限幅到游戏区域，再转换成红色挡板的左上角位置。即使串口长时间无数据，也保持当前坐标，不覆盖按键产生的位置；若从未收到有效串口帧，则默认使用按键控制。

## 6. 音频播放与 WM8978

WM8978 由 I2C 配置寄存器，由 I2S2 提供 PCM 音频数据，DMA 负责持续搬运。DAC 是 MCU 内部模拟输出，两条链路用途不同：

```text
语音/游戏音频：SD WAV -> FatFs -> PCM缓冲 -> I2S2 DMA -> WM8978
模拟波形输出：DAC触发定时器 -> DAC DMA/寄存器 -> 外部模拟引脚
```

两者都可能使用定时器资源，但不代表 WM8978 和 DAC 是同一个外设。I2S 的音频采样率由 I2S PLL 和分频共同决定，WAV 文件应在电脑端预先转换为播放器实际支持的格式，当前语音播放路径使用 PCM、单声道、16 bit、16 kHz。

音效采用“当前音效可被后续高优先级音效打断”的调度策略：

1. 新音效到来时停止或替换当前 DMA 传输；
2. 清除旧文件句柄和缓冲区状态；
3. 打开新 WAV，跳过 WAV 头；
4. 填充首个 DMA 缓冲区并启动传输；
5. 半传输/传输完成回调中继续填充数据；
6. 文件结束后停止 DMA、关闭文件并释放播放状态。

所有播放失败都应回收文件句柄和 DMA 状态，不能让 `audio_busy` 永久保持为真，否则会出现“第一次能响，后续都不响”的现象。整点报时默认关闭；时间设置页面内禁止触发报时，退出页面后再恢复正常触发判断。

SD 卡目录示例：

```text
\MO LE\...
\Miao\xxl1.wav ... xxl5.wav
\Miao\xxljs.wav
\Miao\xxlzd.wav
```

## 7. RTC、闹钟与整点报时

RTC 是时间的唯一可信来源。读取时间后必须按 HAL 要求先读时间、再读日期，以解除影子寄存器锁定：

```c
HAL_RTC_GetTime(&hrtc, &time, RTC_FORMAT_BIN);
HAL_RTC_GetDate(&hrtc, &date, RTC_FORMAT_BIN);
```

闹钟业务保存小时、分钟、秒和使能位。闹钟触发条件应包含“当天目标时间”和“本次已经触发”标志，避免在同一秒内重复触发。触发后弹出全局告警页，确认键停止，返回键延迟 5 分钟；30 秒无操作自动延迟，下一次仍无操作则关闭本次闹钟。

整点报时只在 `minute == 0 && second <= 2` 的窗口内触发，并用日期/小时标志去重。修改时间时设置 `time_setting_active`，该标志有效期间不执行整点报时。

## 8. ADC 示波器与 DAC 波形

### 8.1 ADC

ADC 采样、数据显示和波形绘制分成三个阶段：

1. DMA 或定时触发采样，将原始值写入环形缓冲区；
2. 对采样值做轻量滤波，例如滑动平均或一阶 IIR；
3. 在业务任务中计算直流值、峰峰值、周期、频率、占空比和波形类型；
4. GUI 任务只读取已经计算好的结果并刷新少量控件。

测频不能只依赖单个边沿。应使用带回差的有效区域：上阈值和下阈值之间设置滞回，连续多个周期取中值/平均值，并根据频率动态选择显示时间窗。低频时扩大采样时间窗，高频时降低参与绘图的点数，避免低频波形被重复压缩成多个小波形。

波形判断可使用归一化后的特征：

- 正弦波：上下半周期平滑、峰值附近斜率连续；
- 三角波：上升和下降斜率近似线性且绝对值接近；
- 锯齿波：上升/下降斜率明显不对称；
- 方波：高低电平停留时间明显、边沿集中。

判断结果应加入稳定计数，例如连续 N 次结果一致后才更新 UI，避免 `Sine/Triangle/Unknown` 快速跳变。

### 8.2 DAC

DAC 页面保存波形、频率、峰峰值、占空比和运行状态。频率范围为 0~2000 Hz，频率和峰峰值以 0.1 为步进。位选择控件决定当前修改个位、十位或百位；加减操作采用十进制进位/借位。

实际输出应考虑：

- DAC 满量程受 VDDA 限制，峰值不能超过 3.3 V；
- 正弦/三角/锯齿查表，方波按相位索引生成；
- 使用定时器触发 DAC，采样率由“输出频率 × 每周期采样点数”决定；
- 改参数时先停止 DMA，再更新查表和触发频率，最后重新启动；
- 页面销毁不停止 DAC，只有用户明确按下暂停或离开功能页时才改变输出状态。

## 9. 游戏功能

游戏逻辑与游戏页面分离。游戏状态至少包括：挡板位置、星星/炸弹位置和速度、分数、生命值、游戏状态、难度、串口控制模式。

难度参数建议集中管理：

| 难度 | 星星数量 | 速度范围 | 说明 |
|---|---:|---:|---|
| 简单 | 2 | 3~8 px/帧 | 适合测试输入 |
| 中等 | 4 | 5~15 px/帧 | 默认难度 |
| 困难 | 6 | 8~20 px/帧 | 星星更多、速度更快 |

生成物体时就完成位置规划，检查所有星星和炸弹的最小间距，避免运行过程中重排造成必然漏接或必然碰撞。物体下落采用固定周期更新，挡板位置先根据按键和串口输入合并，再统一限幅到游戏框内部。

游戏音效由事件触发：接星星播放随机星星音效，接炸弹播放炸弹音效，生命耗尽播放游戏结束音效。音频播放失败不能阻塞游戏主循环。

## 10. Flash 掉电保存

设置和历史成绩保存到独立 Flash 扇区，不能覆盖程序代码。当前采用追加式记录（journal）而不是每次修改都擦除整扇区：

```text
扇区擦除
  -> 写入记录1
  -> 写入记录2
  -> ...
  -> 扇区写满后再整体擦除并从记录1开始
```

每条记录包含版本号、递增序号、配置数据和校验值。上电时扫描所有槽位，选择序号最大的有效记录；发现版本不匹配或校验错误时使用默认值。保存时只在离开设置页/返回主菜单或游戏结束时写一次，避免调节参数时频繁擦除和卡顿。

保存内容包括：

- DAC 波形、频率、幅值、占空比和运行状态；
- ADC 显示参数；
- 闹钟 A/B 和相关使能；
- 语音包、游戏音乐包和音量；
- 游戏难度；
- 历史最高分和最近几次分数；
- 必要的界面选择状态。

RTC 当前时间通常不直接用 Flash 保存，而使用 RTC 后备域/纽扣电池保持；用户手动设置时间后由 RTC 继续计时。

## 11. 代码生成与可维护性

CubeMX 生成文件中的用户代码必须放在 `USER CODE BEGIN/END` 区域内。自定义 BSP 文件、LVGL 页面和业务逻辑不应直接写入 CubeMX 会覆盖的生成区。

建议每次重新生成代码后检查：

1. 外设时钟源和分频是否改变；
2. DMA Stream/Channel 是否仍与 USART、I2S、ADC/DAC 对应；
3. NVIC 优先级是否满足 FreeRTOS 约束；
4. `FreeRTOSConfig.h`、`lv_conf.h` 和链接脚本是否保留；
5. Flash 保留扇区是否仍未被程序镜像覆盖；
6. SDIO、FSMC/FMC、I2S 引脚复用是否与原理图一致。

## 12. 推荐实现路径

```text
硬件初始化与单驱动测试
  -> LCD/RTC/按键/LED
  -> SD/FatFs
  -> I2C + WM8978 + I2S DMA
  -> ADC/DAC

RTOS 基础
  -> 确认 SysTick/TIM7 时基
  -> 建立 GUI 任务
  -> 建立音频、采样、闹钟业务状态

LVGL 基础
  -> 显示 flush_cb
  -> 按键 indev
  -> 主菜单和页面导航
  -> 按需创建与三页留存池

功能集成
  -> RTC/时间设置
  -> DAC 参数页
  -> ADC 示波器
  -> 闹钟与音频调度
  -> 游戏和串口坐标
  -> 语音包/游戏音乐选择

可靠性验证
  -> 无 SD 卡启动
  -> 连续播放多个音效
  -> 页面反复进入/回收
  -> 设置保存、断电恢复
  -> 串口连续帧、坏帧、超范围坐标
  -> 低频/高频 ADC 和 DAC 输出
```

每增加一个功能，先验证驱动接口，再接入业务状态，最后由 GUI 显示状态。这样即使某个页面被留存池回收，后台功能仍然可以独立运行，也能避免把阻塞操作带入 LVGL 线程。
